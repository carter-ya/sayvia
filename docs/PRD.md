# Sayvia 产品需求文档

- 文档版本：v0.3
- 产品版本：MVP v0.1
- 状态：部分决策已确认，其余待评审
- 更新日期：2026-10-30
- 品牌及项目名称：Sayvia；代码仓库、包名等使用小写 `sayvia`

Sayvia 是面向 GitHub、Product Hunt 等网站的 AI 翻译 Chrome 扩展，帮助用户阅读其他语言的内容，并在原有编辑框中完成跨语言表达。

首版重点打通“输入内容 → 翻译 → 预览编辑 → 复制或替换 → 用户自行发布”的流程，同时提供选中文字翻译。本文供产品、设计、开发和测试确定首版范围与验收标准。

## 1 产品目标与需求状态

### 1.1 已确认需求

| 编号 | 需求 |
| --- | --- |
| C01 | 使用 Sayvia 作为品牌和项目名称 |
| C02 | 以 Chrome 扩展形态提供网站内容翻译，覆盖 GitHub、Product Hunt 等场景 |
| C03 | 支持将编辑框内的源语言内容翻译为用户指定的目标语言 |
| C04 | 支持将译文原地替换进编辑框，也支持复制译文后由用户自行修改或替换 |
| C05 | 使用 AI 模型翻译，支持 DeepSeek 和 OpenAI 的模型 |
| C06 | 架构需要支持用户配置兼容服务的 API 地址、模型名称等信息 |
| C07 | PRD 使用 Markdown 保存 |
| C08 | API Key 默认永久保存在当前设备，关闭浏览器、重启设备及扩展正常更新后仍可使用 |
| C09 | 首版优先适配 GitHub，Product Hunt 评论框专项适配安排在下一阶段 |

### 1.2 首版范围与规划假设

已确认：GitHub 优先适配；Product Hunt 的评论框专项适配安排在下一阶段。MVP 仍支持获授权页面的通用选中文字翻译。API Key 默认永久保存在当前设备。

其余规划假设仍待评审：采用用户自带 API Key 的模式；翻译由用户主动触发；默认先预览再替换；自定义 OpenAI 兼容接口纳入首版。

### 1.3 产品目标

- 用户能够在网站内完成阅读翻译和写作翻译，无需反复切换翻译工具。
- 用户能够控制哪些内容被发送给哪个模型，以及译文是否覆盖原文。
- 写作翻译保留原意和必要格式，不因翻译丢失草稿或误发内容。
- 增加网站和模型服务时，不需要重写核心翻译流程。

### 1.4 首版不包含

整页自动翻译、自动发表评论、自动回复、对话式 AI 助手、复杂富文本格式回写、账号体系、云端历史同步、会员订阅和平台代付模型费用。

## 2 目标用户与使用场景

首批用户是参与国际开源社区的开发者、浏览和讨论海外产品的独立开发者与产品人员，以及习惯用母语起草外语评论的用户。

| 场景 | 用户需要 | 完成标准 |
| --- | --- | --- |
| 阅读 GitHub Issue 或 PR | 看懂一段正文或讨论 | 选中内容后看到目标语言译文，原文保留 |
| 在 GitHub 回复评论 | 用中文起草英文回复 | 查看并编辑英文译文，再复制或替换 |
| 修改外语草稿中的一句话 | 只翻译选中部分 | 编辑框其余文字和格式保持不变 |
| 使用自定义模型服务 | 填写已有服务信息 | 测试连接成功并完成一次翻译 |
| 在暂不支持替换的网站上写作 | 获得可用译文 | 能在预览面板复制译文并手动粘贴 |

### 3.1 网站与编辑器支持边界

| 对象 | MVP 支持程度 |
| --- | --- |
| GitHub Issue 和 PR 页面中的常规纯文本评论框 | 核心验收范围，支持全文、选区、替换和恢复 |
| GitHub Discussions 中的常规纯文本评论框 | 纳入兼容验证；未通过验证的编辑器只提供预览和复制，并明确说明 |
| 其他获授权网站的普通 textarea 和文本 input | 提供通用适配，通过运行时检查后才启用替换 |
| Product Hunt | MVP 支持获授权页面的选中文字翻译；评论框专项支持属于 P1 |
| contenteditable、富文本、代码编辑器及跨域 iframe | MVP 不承诺通用回写，提供可用的预览与复制入口 |
| 浏览器内部页、扩展商店等受限页面 | 提示该页面暂不支持，用户可以在扩展面板手动粘贴翻译 |

GitHub 页面是否通过适配，以编辑框内容和网站实际提交状态一致为准，不能仅凭文字在界面上发生变化判断成功。

## 4 信息架构与交互入口

### 4.1 浏览器工具栏弹窗

显示默认模型、阅读目标语言、写作目标语言、当前网站授权状态和设置入口。提供手动粘贴文本翻译，作为不支持页面的备用方式。

### 4.2 页面内翻译面板

承载原文、目标语言、译文编辑、请求状态和操作按钮。阅读模式提供“复制译文”和“关闭”；写作模式根据编辑器能力增加“替换选中内容”或“替换全文”。成功替换后显示“恢复原文”。

同一标签页只保留一个活动翻译面板。出现未应用的译文编辑时，切换任务或关闭面板前提示是否放弃。面板不得因点击页面空白处意外丢失结果。

### 4.3 设置页

包含模型配置、语言偏好、翻译模式、网站权限、快捷键入口和本地数据清理。

### 4.4 触发入口

- GitHub 已适配评论框附近显示翻译按钮。
- 页面选区通过右键菜单或快捷键翻译。
- 工具栏弹窗支持翻译当前可识别编辑框，或手动粘贴文本。
- 快捷键遇到冲突时，提示用户在 Chrome 快捷键设置中调整；不抢占网站常用输入快捷键。

## 5 核心用户流程

### 5.1 首次使用

1. 用户打开 Sayvia，看到简短用途说明。
2. 选择 OpenAI、DeepSeek 或自定义服务，填写 API Key 和模型。
3. 运行“测试连接”，成功后设为默认模型。
4. 分别确认阅读和写作的目标语言；初始建议为简体中文和英语。
5. 在网站上首次触发时申请对应权限。用户拒绝后仍可使用手动粘贴翻译。

测试连接使用公开的固定测试短句，不发送当前页面内容，并提示可能产生少量服务商费用。配置缺失时给出直接设置入口，不触发无效翻译。

### 5.2 阅读翻译

1. 用户在获授权页面选中一段文字。
2. 通过右键菜单或快捷键启动翻译，同时捕获选区内的代码、链接标签及段落等必要结构，不能只提取纯文本后丢失代码身份。
3. 面板展示原文、目标语言和当前模型。
4. 翻译成功后展示译文，用户可以编辑、复制或重新翻译。
5. 页面原文保持原样。

### 5.3 写作翻译

1. 用户在支持的编辑框输入草稿。
2. 用户点击翻译按钮或使用快捷键。
3. 存在非空文本选区时翻译选区，否则翻译全文；操作前明确显示处理范围。
4. 默认在面板预览译文，用户可以修改译文。
5. 用户选择“复制译文”或“替换选中内容／替换全文”。
6. 替换前检查原草稿、编辑框和选区是否仍有效；成功后提供恢复入口。
7. 用户自行点击网站的提交按钮。

### 5.4 快速替换

用户可以在设置中主动开启快速替换；此模式只影响写作翻译。结果完整返回、格式检查通过且草稿未变化时，自动替换目标范围并显示恢复入口。任何条件不满足时转为预览，并说明未替换的原因。

## 6 翻译内容与语言规则

### 6.1 语言

- 阅读和写作分别保存目标语言，单次操作允许临时更改。
- 默认自动识别源语言，也允许手动指定。
- 首版目标语言选项为简体中文、繁体中文、英语、日语、韩语、法语、德语和西班牙语；实际效果纳入翻译质量验证。
- 混合语言按目标语言翻译自然语言部分，保留代码和标识符。
- 不因自动识别结果与目标语言相同而静默跳过；允许用户继续翻译。

### 6.2 翻译原则

忠实表达原意，使用自然、适合社区交流的措辞。保留否定、时间、版本号、数量、因果和不确定性；不新增承诺、事实、结论或礼貌性长篇内容。默认只输出译文，不添加解释、标题和引号包装。

输入内容作为待翻译材料处理，其中的命令或角色描述不能改变翻译任务。模型输出按不可信文本展示，不执行其 HTML 或脚本。

### 6.3 格式保护

格式保护根据输入来源处理：编辑框中的 Markdown 保留其源文结构；网页阅读选区依据已渲染页面中的代码、链接和段落信息识别保护内容；手动粘贴默认按纯文本处理，不猜测已经丢失的网页格式。

代码块、行内代码、URL、Markdown 链接目标、GitHub 用户提及和 Issue／PR 引用等受保护内容须保持原样；自然语言链接标签可以翻译。保留 Markdown 的列表、引用、标题和段落结构，允许目标语言所需的标点变化。网页中标记为代码的 timeout 等标识符，即使选中文本没有反引号，也必须原样保留。

阅读译文仍以文本展示，不回写原网页或重建可交互 HTML。跨链接选区中的自然语言标签应能翻译，原网页链接及目标保持不变；不为了翻译读取选区外正文、链接隐藏属性或整页 HTML。

受保护内容应在请求前提取或使用等效机制处理，并在返回后校验。校验失败、结果为空或输出被截断时，不得自动替换或启用普通替换；面板可以保留已返回内容并明确标注异常，允许用户复制或重试。

### 6.4 输入边界

MVP 单次输入上限暂定为 12,000 个 Unicode 字符，是产品限制，不代表模型上下文限制。超过时提示缩小选区，不截断草稿后静默翻译。空文本、只有空白或只有受保护内容时不发起请求。

首版采用完整结果返回后再编辑和替换的方式。流式展示不属于 MVP 发布条件。

## 7 复制替换与恢复规则

| 操作 | 行为与约束 |
| --- | --- |
| 复制 | 复制当前译文编辑区内容；成功后提示已复制；失败时保留文本并允许用户手动选择复制 |
| 替换全文 | 只替换发起任务时绑定的编辑框，不因焦点变化改为另一个编辑框 |
| 替换选区 | 只替换记录的源选区，其余文本保持不变；保留必要的光标与编辑状态 |
| 草稿变化 | 请求后或预览期间，源编辑框内容一旦发生变化，该任务的替换资格失效；即使之后改回相同文字也需重新翻译 |
| 编辑器失效 | 编辑框被移除、页面跳转、站点重新渲染或选区无法验证时禁用替换，仍允许复制已完成结果 |
| 恢复原文 | 每个编辑框保留最近一次成功替换的恢复快照；仅当当前内容仍等于该次替换后的内容时才能恢复 |
| 恢复冲突 | 用户在替换后继续编辑时，不覆盖现稿；提供查看和复制此前原文的方式 |
| 连续替换 | 同一编辑框的新成功替换覆盖上一条恢复记录；仅保证一步恢复 |
| 生命周期 | 原文、译文和恢复快照仅在当前标签页任务会话中保留；页面刷新、关闭或会话结束后不保证恢复 |

复制永远不修改网页草稿。翻译失败、取消或面板关闭不得改写草稿。扩展不得触发网站的发送、保存或提交操作。

## 8 模型与服务配置

### 8.1 配置字段

| 字段 | 规则 |
| --- | --- |
| 配置名称 | 必填，允许多份配置，例如“日常翻译”和“工作模型” |
| 服务类型 | OpenAI、DeepSeek、自定义 OpenAI 兼容服务 |
| API Base URL | 内置服务预填，自定义允许填写；展示最终请求地址供核对 |
| API Key | 默认永久保存在当前设备，隐藏显示，支持更新、清除；首版支持 Bearer Token 鉴权 |
| 模型名称 | 内置服务可给出预设，始终允许手动输入，不依赖模型列表接口 |
| 接口协议 | MVP 支持 Chat Completions 格式；协议适配层预留扩展能力 |
| 默认配置 | 全局指定一份；切换配置只影响新任务 |
| 连接状态 | 未测试、测试中、可用、失败；修改地址、凭证或模型后旧测试状态失效 |

首版自定义服务要求兼容已支持协议及其文本返回结构，不承诺接入任意 HTTP 接口。自定义请求头、任意路径映射、OAuth 和 Responses 等新增协议放入后续版本。

### 8.2 地址规则

允许用户填写服务商文档中的 Base URL，包括必要的路径前缀，不盲目添加或删除版本路径。界面明确提示填写 Base URL 而非完整请求地址，避免重复拼接。

远程服务要求 HTTPS；本地回环地址的 HTTP 模式单独提示并单独授权。请求域名必须来自用户保存的配置，网页和待翻译文本不能指定请求地址。跨域重定向不得自动携带凭证继续请求。

### 8.3 连接测试与错误

“测试连接”执行一次最小文本生成，验证鉴权、模型、权限、协议和可解析的文本响应。错误应区分地址或权限问题、凭证无效、模型不可用、额度或限流、协议不兼容、网络及超时。

服务配置失败时不自动切换其他服务商；译文和原文也不得自动发送到备用域名。

### 8.4 凭证保存

API Key 随服务配置默认永久保存在当前设备，无需勾选“记住”或每次重新输入。浏览器关闭、设备重启、扩展后台重启以及扩展正常版本更新不得清除凭证；正常更新涉及存储迁移时必须保留现有配置及凭证。

永久保存指扩展不设置自动过期时间，凭证保留至用户主动更新、清除或删除对应配置。卸载扩展、清除扩展存储或删除浏览器配置文件后，不保证恢复凭证；服务商侧的 Key 过期或撤销不由扩展控制。

凭证不参与浏览器同步、不写入网页 DOM、不传给网页脚本、不进入日志。限制本地存储访问范围，使页面内容脚本无法直接读取。保存位置与清除方式在设置页说明，本地持久保存不等同于加密保险箱。删除配置时删除其凭证，提供清除全部本地数据的入口。

如果未来提供 Sayvia 自有额度，服务商主密钥必须由服务端持有，并另行设计账号、计费和限额；不得打包进扩展。

## 9 权限与隐私

- 按需申请网站访问权和模型 API 域名访问权；拒绝授权时解释受影响的功能并保留其他入口。
- 首版只上传用户本次明确选择或主动翻译的文本、必要格式信息和翻译指令，不上传整页、相邻评论、Cookie 或网站登录凭证。
- 首次使用及切换自定义服务时告知内容会发送至所选服务商；日常翻译不反复弹确认框。
- 私有仓库内容仍由用户主动触发。界面明确显示当前服务商；不自动提取仓库上下文。
- 密码框以及标记为支付卡信息的输入框不提供翻译或读取入口。
- API Key 按第 8.4 节在本机永久保存；翻译原文、译文和恢复快照仍仅保留于任务会话。清除全部本地数据会删除服务配置、API Key、偏好及可控的会话数据，操作前明确提示将需要重新配置。
- MVP 不上传使用分析数据。运行日志只记录不含文本、凭证和私有 URL 的错误信息；任何未来遥测需要另行设计知情选择。
- 模型服务商对数据的处理由其政策决定，隐私说明应链接对应政策，不能声称本地不留存就意味着服务商不留存。

## 10 任务状态与异常处理

| 状态或异常 | 用户反馈 | 处理规则 |
| --- | --- | --- |
| 待配置 | 配置模型服务 | 保留源文本并提供设置入口 |
| 待授权 | 授权当前网站或 API 域名 | 用户拒绝后不循环弹窗 |
| 翻译中 | 明确显示当前模型、处理范围和取消按钮 | 禁止重复点击产生相同并发请求 |
| 成功 | 展示可编辑译文和可用操作 | 仅完整且校验通过的结果具有替换资格 |
| 草稿已变化 | 原文已修改，请重新翻译 | 保留结果供复制，禁用替换 |
| 凭证或额度错误 | 显示可理解原因和设置入口 | 不自动重试 |
| 限流或临时网络错误 | 提示稍后重试 | MVP 由用户手动重试，避免隐性重复费用 |
| 超时 | 提示服务响应超时 | 总请求超时暂定 60 秒，失败不改写草稿 |
| 取消 | 显示已取消 | 尽力终止请求并忽略迟到结果；提示取消不保证服务商停止计费 |
| 结果为空或格式损坏 | 说明结果不可直接应用 | 保留原文，禁用替换，允许重试 |
| 编辑器不支持 | 此编辑器暂不支持直接替换 | 提供预览、复制或手动粘贴入口 |

同一标签页一次只运行一个翻译任务。翻译中再次触发其他文本时提示先完成或取消当前任务。不同标签页可以独立运行；每个请求与标签页、编辑器、源文本版本和服务配置绑定，过期结果不得应用到新任务。

## 11 非功能要求

以下数值是首版验收目标，需在测试环境记录实测结果，不作为尚未完成的性能承诺。

| 类别 | 验收要求 |
| --- | --- |
| 交互反馈 | 普通桌面环境中，触发后 200 毫秒内显示面板或处理中状态；模型生成耗时单独记录 |
| 浏览器兼容 | 支持发布时 Chrome 稳定版及前一主版本；发布前记录实际测试版本 |
| 页面兼容 | GitHub 常规页面导航、动态评论框出现与站点重渲染后，不出现重复按钮或跨草稿替换 |
| 页面性能 | 无活动任务时不持续轮询；页面观察与事件监听需限制范围并在退出时清理 |
| 稳定性 | 网络中断、任务取消、扩展后台中断后均不丢失网页草稿，不重放已失效任务 |
| 可访问性 | 核心按钮有可读名称，可用键盘完成翻译、复制和关闭，关闭后合理恢复焦点 |
| 外观 | 面板适配浏览器可见区域，支持明暗主题，长文本可滚动且操作按钮可访问 |
| 安全 | 凭证不暴露给网页；模型结果不作为脚本或未经处理的 HTML 执行 |
| 可维护性 | 网站适配、翻译流程和模型协议分层，新增适配不改变复制及覆盖保护规则 |

实现采用 Chrome Manifest V3。模型请求由扩展后台或其他受控扩展上下文发起，页面内容脚本只负责已授权页面的交互。长请求需要考虑后台生命周期，具体框架、通信和持久化实现由技术设计确定。

## 12 验收场景

| 编号 | 前提与操作 | 预期结果 |
| --- | --- | --- |
| A01 | 首次进入，尚未配置模型就启动翻译 | 引导配置，不发送请求、不改变草稿 |
| A02 | 分别配置 OpenAI、DeepSeek 和一个符合协议的自定义测试服务 | 各自通过连接测试并完成一次翻译，错误配置可定位原因 |
| A03 | 在 GitHub Issue 和 PR 评论框输入中文 Markdown 后翻译成英文 | 看到英文预览；代码、URL、用户提及及引用保持原样 |
| A04 | 只选中草稿中的一段并替换 | 仅该选区被替换，其余文字逐字保持不变，网站读取到新内容 |
| A05 | 编辑译文后点击复制 | 剪贴板是修改后的译文，网页草稿未变化 |
| A06 | 替换成功后立即恢复原文 | 精确恢复最近一次替换前的草稿，网站状态同步 |
| A07 | 翻译中或预览期间继续修改源草稿，包括改动后再改回 | 当前任务不覆盖草稿；禁用替换并保留译文供复制 |
| A08 | 替换后继续写作，再点击恢复 | 不覆盖新增内容，可查看或复制此前原文 |
| A09 | 用户开启快速替换后执行成功、失败及格式校验失败任务 | 只有完整、有效且草稿未变化的任务自动替换，其他情况保留原文 |
| A10 | 在获授权页面选中文字执行阅读翻译 | 展示原文与译文，页面内容保持原样；阅读与写作目标语言独立 |
| A11 | 请求发出后切换焦点、删除编辑框、跳转或触发重渲染 | 结果不会写入其他编辑框；失效任务只能复制 |
| A12 | 模拟凭证错误、限流、超时、断网、取消和迟到响应 | 提示对应原因，不自动重复调用，不修改草稿或应用过期结果 |
| A13 | 拒绝网站或 API 权限，或在受限页面使用扩展 | 不越权运行，明确说明限制，手动粘贴入口可用 |
| A14 | 输入超长文本、空文本、只有代码或包含脚本片段的文本 | 边界符合第 6 节；不静默截断，不执行脚本 |
| A15 | 使用不支持的富文本编辑器 | 不显示可用的直接替换承诺，提供复制路径 |
| A16 | 保存、切换及删除服务配置；清理全部本地数据 | 新任务使用正确配置，旧任务不混用凭证；删除配置时删除对应 Key，清理全部数据前提示并按确认范围清除 |
| A17 | 使用 Tab 和键盘操作面板，切换明暗主题和窄窗口 | 核心流程可完成，正文和操作按钮可见 |
| A18 | 检查 GitHub 评论的实际提交载荷，提交操作由测试者手动完成 | 使用替换后的文字；扩展从未代为提交 |
| A19 | 保存 Key 后分别关闭并重开浏览器、重启设备、重启扩展后台及正常升级扩展 | 无需重新输入 Key，配置与默认模型保留；使用仍有效的 Key 可以继续翻译 |
| A20 | 选择已渲染正文，其中包含行内代码 timeout、代码块、自然语言链接标签；另测只选代码一部分和跨链接选区 | 代码选中部分逐字保留，自然语言正文和链接标签可翻译；不越过原选区，不修改网页或执行 HTML |

翻译质量使用至少 30 条经人工确认参考含义的样例，覆盖 Issue 描述、技术回复、否定与条件、数字版本、混合语言、Markdown 和礼貌表达。发布时要求：受保护内容在固定样例中 100% 保留；不得出现改变结论、否定或承诺的严重语义错误；至少 90% 样例经人工评审可直接使用或只需轻微措辞调整。分别记录服务、模型、配置和测试日期；质量结论仅覆盖实际测试组合。

## 13 效果评估与发布条件

MVP 通过人工体验、测试记录和用户主动反馈评估，不依赖上传分析数据。后续如果加入可选遥测，应先定义事件、采集范围与用户开关。

| 评估项 | 定义或记录方式 |
| --- | --- |
| 首次配置可用性 | 新用户能否独立完成配置、连接测试和首次翻译；记录卡点 |
| 请求成功率 | 在服务可用、权限完整的有效测试请求中，返回完整且可校验译文的比例；取消、配置错误单列 |
| 译文可用性 | 按第 12 节固定样例与人工标准评审 |
| 任务完成效率 | 记录从触发到完成复制或替换的时间，同时区分模型等待时间 |
| 草稿安全性 | 覆盖保护、复制、恢复和取消等验收场景中误覆盖和自动提交次数必须为零 |

MVP 发布须满足全部 P0 验收，明确列出已验证的网站和编辑器；完成固定样例翻译质量验证、凭证与权限检查、隐私说明和使用说明。Product Hunt 专项适配、整页翻译及商业化功能不作为 MVP 发布条件。

M1 的真实模型样例至少覆盖普通评论、含代码的长句、列表和链接、混合语言及需要调整语序的句子，并覆盖 Markdown、网页选区和纯文本三类输入。每个拟进入 MVP 的内置服务至少选择一款模型运行同一组小样本；固定样例、首轮成功率、人工评审与耗时记录及退出条件见技术方案。模拟 API 仅用于异常和生命周期测试，不能代替翻译算法验证。M3 仍执行第 12 节完整发布质量评审。

此处只定义依赖和交付顺序，工作量与日期待技术验证后估算。
