# 阅读预览与格式保留验证

代码基线：f54dd85039e4a3322d0f8e0016dfdebc271b3b10，算法 segments-v2.3。

用户提供的 [公开 PR 描述](https://github.com/exc-works/decimal/pull/8) 有 731 个可见字符、6 处行内代码和 6 个链接（含重复 #9）。此前 3 行 textarea 即使手动拉伸也受高度限制，DOM 平文缺少链接目的地与代码样式。

阅读现在默认排版预览；长结果自动加宽、展开并在必要时滚动，操作按钮位于结果滚动区之外。编辑切换到自动增高的 Markdown 文本框，复制后保留代码和链接语法。原文显示和字数仍采用冻结的可见文本。

格式提取在原有可见性和 Range 裁剪之后进行。代码、段落、链接在本地生成 Markdown，并仍以 dom-selection + format=markdown 进入原有 Worker；源中不得混入旧平面区间。链接目的地只读取选中、可见链接，限制为不含认证信息的 HTTP／HTTPS 地址；目的地与文本共同参与快照校验。未选中或隐藏链接不读取；URL 与代码内容不发给模型。

浏览器只渲染受限 React 节点；原始 HTML 作为文本，图片仅显示说明，不加载远端图片。不安全 URL 不可点击；安全链接要求可信点击，使用 noopener／noreferrer。模型响应和本地格式保护没有弱化。

验证包括：

- 380 项单元测试通过，含部分代码/链接选区、代码链接、隐藏与未选中 href 不读取、href 变化冻结失效、裸 pre 仍可翻译及矛盾输入拒绝。
- Chrome 156 的完整 98 项浏览器回归通过；最终原文自动增高等改动另通过 11 项相关浏览器测试。
- 长 PR 预览可滚动、复制/编辑按钮可见；编辑/完成切换、实际剪贴板粘贴保留 Markdown；375px 窄屏、深色主题、可信链接新标签页打开与 opener 隔离通过。
- OpenAI gpt-6-luna 与 DeepSeek deepseek-flash 各验证完整描述和部分选区，共 4 次真实请求。全部结果通过 Markdown 结构检查，代码值和目标地址逐项一致；链接目标不在模型请求中。
- 界面截图在隔离配置中重放已记录的 OpenAI 结果，先验证请求与实测输入完全一致，再经生产翻译链路渲染。截图阶段没有额外真实模型调用，也没有提交 GitHub 评论；原页面正文未修改。

[逐样例数据](reading-preview-20261102.json) 仅含公开描述、译文、usage 与结构验证。原始模型 JSON 留在本机忽略目录（0600）；Key、认证头、环境文件不提交。人工语义和可用性验收仍待完成；例如 DeepSeek 对 tie 有“平局”的术语译法，不能把结构通过视为译文措辞已完全合格。


审核修复：缩进正文的行首空白以本地字符引用保留，避免四空格或 Tab 被重新识别为代码；普通实体样式文本与链接目标中的 & 分别按所在 Markdown 上下文转义，自动链接保留原始语义。针对这两处问题及相关实体文本的 3 个回归先在旧代码失败，再在修复后通过。另复现了预览 href DOM 被改写后跳到错误目标，点击现在使用冻结的安全地址，与可变 DOM 属性分离；主要和中键点击都受可信事件约束。

公开 PR 样例的序列化输入与既有真实调用记录保持完全一致，后续修复使用同一记录在新生产构建中重放验证，不额外发起付费模型请求。


第二轮修复：裸网址只在相邻代码／链接语义边界之间识别，避免 URL 匹配跨过保护区间而泄露代码或丢失链接目的地。句末标点与配对括号由既有 GFM 解析器决定；实体样式的可见 URL 查询值保持字面含义，选中目的地中的反斜杠也正确转义。新增的相邻代码、相邻链接、句末句点/感叹号、平衡括号和反斜杠 6 项回归先失败后通过。
