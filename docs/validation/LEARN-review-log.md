# LEARN 研究证据与独立审核记录

日期：2026-11-03。当前实现契约见 [LEARN_IMPLEMENTATION](../LEARN_IMPLEMENTATION.md)。这份记录区分方案可实施性、原型验证和产品验收，不能互相替代。

## 独立技术审核

审核者：独立 agent `technical_review`。只读审核主方案、源码边界及真实证据，没有参与修改。最终结论：**技术方案通过，当前无待修 P1/P2 方案问题；可以创建堆叠实现 PR。** 无需为最终复审再改方案；运行验收及各 PR 的 `@codex review` 仍需执行。

| 发现 | 修订及结论 |
| --- | --- |
| P1：没有未来 cue 证据，异步开启可能错过首个响应 | 两视频各人工／ASR 的正常 XHR 实证；站点本地捕获授权与当前视频翻译授权分开，动态注册 MAIN document_start 后才算启用 |
| P1：字幕没有独立任务契约 | 新增 captions purpose、独立来源／结果；同步扩展 route、execution、Worker 与恢复 |
| P1：显式任务优先与现有 TASK_BUSY 冲突 | broker 串行区先取消字幕批次并失效结果，再启动显式任务 |
| P1：源轨／广告身份不明确 | 明确视频＋语言＋kind＋name＋tlang；原生菜单选轨，只读私有接口缺失时停止接管；广告实测列为门槛 |
| P1：TTS 后台回收、旧回调所有权不明 | 持久化租约、epoch、精确所有权、下一次唤醒清理；不承诺回收瞬间停止 |
| P2：ASR 延长空档、追加文本提前出现 | end 取原 end 与下一行起点的较小值；追加按时间拆 revision；同起点、零时长和无父行有明确规则 |
| P2：分块重组可能无界 | 每响应 4 MiB／256 块，最多两个响应／8 MiB，10 秒，64 消息每秒；响应 ID、连续序号和取消清理 |
| P2：stop 先于 start 无法失效 | 后台预签短期 ticket，取消记录不提前驱逐，旧 epoch 拒绝；活动租约 stop 不受 ticket 启动期限影响 |
| P2：扩展失效后原生字幕可能仍隐藏 | 有限显示租约及页面看门狗恢复；完全冻结只能在恢复执行后清理，真实失效测试仍待实施 |
| P2：lookup schema／长度和迁移不明 | 明确字段及输入、结果、语言上限，旧数据默认 translate，手动草稿结构隔离 |

审核额外核对 Chrome 116 源码：打包扩展 alarm 最小 60 秒且可能延迟；不能把当前开发浏览器表现当成 Chrome 116 保证。新版本 API 不作为首期依赖。来源链接在实现契约第 7 节。

四个轨均取得非空 JSON3 及未来时间轴：eIho2S0ZahI 人工 229 行、ASR 284 行；arj7oStGLkU 人工 315 行、ASR 335 行。计数来自诊断解析器，不代表正式 ASR 规范化通过。原文重绘、恢复、全屏、站内换视频已经观察；中途捕获关闭再开启不会自动重放已缓存响应，也已复现。播放器实际源轨与缓存必须精确匹配。

两个已有模型（gpt-6-luna、deepseek-flash），七语言各五个词，每个提示版本最多 70 次，无自动重试。请求通过本机已有凭证，报告不包含凭证。格式结果与语义结论分开。

v2 提示增加“只解释源语言原词，不迁移翻译词义、不重复，区分词形，不确定词性 null”。结果说明提示改善有效但无法保证语义正确。L01b 生产提示应进一步减少无把握形态说明，例句必须对应义项／词形，无法确定时 example／note 为 null，并在固定回归中记录结果；不无限重跑直到得到一份好结果。

以上残余属于真实模型的已知质量风险，仍需在 L01b 处理及记录，不能在 L00 宣称产品语义验收通过。UI 明确 AI 解释可能出错，系统朗读只读原词，不代表某一义项准确发音。不为此引入完整词典、人工音源或虚构置信度。

词形审查依据：[教育部“银行”](https://dict.revised.moe.edu.tw/dictView.jsp?ID=156656&la=1&powerMode=0)、[大辞泉“生”](https://kotobank.jp/word/%E7%94%9F-78786)、[Usito fils](https://usito.usherbrooke.ca/d%C3%A9finitions/fils)、[fil](https://usito.usherbrooke.ca/d%C3%A9finitions/fil)、[doux](https://usito.usherbrooke.ca/d%C3%A9finitions/doux)、[PONS umfahren](https://de.pons.com/%C3%BCbersetzung/deutsche-rechtschreibung/umfahren)。

## 真实字幕模型批次

[v1 指标](youtube-real-model-results.json)：两条实际字幕轨、三个播放位置、两个模型，共 12 次。每批 12～15 个源行，约 30 秒视频；12/12 ID／数量校验通过，完整返回 2.815～9.367 秒。首次开启及跳转时前几条字幕可能已经播放，不能用“到批次末尾的剩余时间”为正宣称全部来得及。它只支持有限预取的吞吐可行性。

独立语义审查：人工轨六批总体可用；ASR 六批发现事实重复、邻行语义移动和识别噪声放大。DeepSeek 在 arj7oStGLkU／120000 的 c2、c3 重复“两个通宵”；两个模型在 c11/c12 调整“我们见过”的位置；OpenAI 将重复 hours 扩成再次强调 72 小时。ID 匹配不能证明语义正确。

[v2 指标](youtube-real-model-v2-results.json)：同一 12 批显式回归，协议全部通过。旧的通宵重复改善，但 behind the / wheel 仍发生关系重复、碎行难读；人工轨存在代词译义不清等 P3。DeepSeek／ASR／300000 用时 **22.998 秒**，超过 2 倍速批尾预算 15.980 秒，余量 **−7.018 秒**。不能保证所有批次赶得上。

据此停止继续只调提示，改为本地 ASR 有界分组：全轨先确定组、同窗口无空档、最多合并 3 行／8 秒／200 码点，保留源行映射；整组原文／译文按同一组时间显示。修订生效边界不合组，模型不决定时间。独立技术审核认可该修订，要求组身份稳定、单行超限不截断、明确组内后续词可提前出现、组内及相邻组语义分别验收。

[分组探针](youtube-grouped-model-results.json)固定提示、改变输入结构，三位置两模型共六次，六次协议通过；完整响应 5.230～8.696 秒。这是结构备选验证，不用其较快结果抹掉 v2 慢响应。独立语义审查确认 behind the wheel 的重复关系与通宵重复消除，多数句子可读性改善；但 OpenAI／300000 的 c3 漏译 that works fine，c1–c2 将“对过去没有记忆”变成“一无所知”，DeepSeek 仍有组间碎片，邻组语序调整仍存在。结论是结构方向可实施，模型语义仍有已知风险，不再靠反复调用挑选全好结果；L04 做固定回归及连续观看验收。分组窗口边缘扩大，性能也不能当作与 v2 完全等负载的对照。

## L01a.2 任务接线审核（2026-11-04）

查词与字幕接入生产 broker、offscreen、Worker 和独立 learning 结果事件。旧任务默认 translate；lookup/captions 始终只读，手动查词用 lookupResult 保存，切换用途生成新的任务身份并清除旧结果。字幕每次发送前及结果交付前复核身份与授权，生产默认拒绝，直到 L03 接入当前视频授权管理器。

独立 agent `technical_review` 初审复现后台重启时取消确认丢失、随后查词与旧字幕并发的问题。修复为持久化 cancelPending，占用同 tab／全局槽位且禁止旧结果交付。复核又定位三处相关边界：清除配置丢失占位、交付失败后的状态组合非法、执行器消失后占位无法解除。均已修复并增加行为测试；最终独立复审无剩余 P1/P2。

保守失败行为：执行器暂时失联时保留占位；确认终态、浏览器证明旧执行器不存在或 epoch 已替换时才释放。清除配置立即删除 Key／草稿／结果，只保留必要的无正文取消记录，确认后按既有保留期清理。

558 项单元测试、类型检查、lint、生产构建通过。真实扩展局部验证通过：两类任务使用打包 Worker，页面查词只读、重复启动去重、取消中止网络、手动查词跨弹窗恢复。使用本机模拟模型响应，未追加真实模型请求；不把这一层当成 UI、声音或 YouTube 连续双语显示已验收。

PR #50 首次 head b02b5bc 的 Codex 审核提出有效 P2：显式抢占先发送 cancel 再保存占位，若 cancel 和后续 query 连续失败，route 仍会变成 interrupted 并提前释放。修复为先持久化取消占位，再发 cancel；字幕查询失败／超时同样进入取消确认路径。增加“取消丢回执→reconcile 失联→再次查词仍拒绝”和直接查询失联回归。原始 head 的 154 项浏览器回归通过；修复 head 的审核与 CI 另行核对。

修复 head `24e97615228bd687a3110c3b50ed268aba37b6b5` 的 [Codex 复审](https://github.com/carter-ya/sayvia/pull/50#issuecomment-6610151332)无新问题，CI 通过，原 finding 已回复并解决。无需追加修复，未合并。

## L02a 本地朗读验证（2026-11-04）

生产后台接入本地声线筛选、短文本／显式语言协议、随机播放身份、幂等票据、会话租约、专用 alarm、导航／关闭取消和重启清理。声线必须 remote=false、无扩展引擎、名称无冲突；zh-HK／zh-MO／yue 与其他 zh／cmn 分组，避免粤语和普通话相互回退。没有声线时不播放，也不改变模型卡片。

独立 agent `technical_review` 实测发现两项 P2：调用方 clientSpeechId 被复用导致旧 alarm 停掉新播放；被新请求抢占的排队 start 返回 canceled 却仍保存 starting。已改为后台随机 speechId、保留终态幂等记录，并同步更新被抢占状态；28 项语音生命周期／声线测试包含这些回归，最终独立代码复审无剩余 P1/P2。

真实扩展 fixture 仅替换 OS 语音引擎，生产消息路由、存储、alarm、SpeechService 仍真实运行。验证只读播放、重复请求不重播、设置页伪造拒绝、关闭目标 tab 清理，以及通过 CDP 实际终止后台后重新唤醒：旧租约先 stop、旧 epoch 拒绝、无自动重播。此 fixture 不证明真实发音质量。

[真实系统探针](speech-native-probe.ts)在独立 Chrome 156.0.8078.4 临时配置运行生产服务、原生 chrome.tts 和默认音量。[两次事件记录](speech-native-initial-results.json)及[补充声线记录](speech-native-results.json)均为七语言原生播放，各自全部产生 speaking→ended，无超时。初次 getVoices 返回空列表，随后生产有限重查成功；后一次探针把声线快照改在 start 后采集，看到 180 个本地声线。表中的 availableMatchingVoiceAfterStart 是该时刻匹配候选，不声称是底层引擎的独立选声回执。样音为固定问候词，未调用付费模型或云端语音。

真实事件完成不等于听感或词义对应读音正确。人工音质／母语评分未完成，仍是发布验收边界；Chrome 116 alarm 最小间隔的兼容性也不由 Chrome 156 短计时表现替代。本层暂未开放产品卡片入口，下一层接入。

本层检查：类型、lint、format、生产构建、588 项单元测试、155 项浏览器测试通过。实际终止后台的新增步骤另行定向复跑通过；没有额外模型调用。
