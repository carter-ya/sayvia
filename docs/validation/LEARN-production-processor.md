# L01b 生产处理器验证（2026-11-04）

范围：查词／字幕的模型调用与实际 Worker 校验分支。后台路由、任务恢复、卡片和语音仍由后续层交付；本层未开放用户入口。

## 实现及独立代码审核

普通翻译与学习任务共用受控网络传输。学习任务一次普通 Chat Completions 请求，完整结果才校验展示；兼容返回 SSE 的服务时仅提供状态和用量，不展示半份 JSON。Worker 不接收 Key，字幕时间和网页身份不进入模型载荷。

独立 agent `technical_review` 初审发现 P2：bootstrap 对合法 RPC ID 的非法输入静默丢弃，使错误拖到 TIMEOUT。已修复为已知类型／合法 ID 立即返回 `{id,ok:false}`，不带原始错误；未知类型及非法 ID 仍忽略。测试直接加载生产 bootstrap，覆盖非法 lookup／caption、有效准备和严格结果校验。最终独立复审无剩余 P1/P2。

取消、超时、晚到结果、Worker 释放、源输入快照、解码后的凭证回显均有测试。保留上一层的兼容性修复：Key 恰好是 JSON 字段名时不误报，真正展示文本中的字面及 Unicode 转义凭证仍拒绝。

## 独立语义审查及处理

`lookup_quality_review` 逐条审查 82 条，不是人工母语认证，没有额外模型请求。结论：结构可行，仍有已知语义错误，不继续重跑以挑选全好结果。

| 样例 | 结果及处理 |
| --- | --- |
| 银行、显式日语生、fils、umfahren | 本轮未复现此前错误；不据此承诺以后不会出错 |
| OpenAI kind，results[16] | P2：把 kindness 的“善意／体贴行为”作为 kind 名词义。保留错误，纳入正式发布语义验收；UI 必须标明 AI 解释可能有误 |
| DeepSeek llama，results[65] | P3：仍称“羊驼”，名称易与 alpaca 混同，保留已知精确性问题 |
| OpenAI doux，results[46] | P3：注释只说阳性单数，遗漏阳性复数同形；例句正确 |
| 两服务 auto／生，results[74–75] | 自动判断为中文，未反映中日文歧义。**非 null 语言不能当成用户已确认**；修改 TTS 契约为自动语言只作建议，朗读前明确确认／纠正，可在带语言名的播放按钮一次完成 |
| auto 食べる、은행 | 四条结果合理，不能据此推断所有自动识别可靠 |
| 未知字符串 | 两条均 null，没有编造词义 |
| 两个指令式输入 | 四条均保持 JSON 解释／拒绝执行，无观察到格式劫持；小样本不是全面提示注入认证 |

kind 的复核依据：[Cambridge kind](https://dictionary.cambridge.org/dictionary/english/kind)。其余词形依据及前两轮失败保留在 [研究审核记录](LEARN-review-log.md)。上述质量风险不伪装为代码修复已消除；不新增词典服务或虚假置信度来掩盖它们。真人发布验收仍按既有门槛执行。

## 真实字幕输出兼容性回放

将前两轮及分组轮的 **30 份真实字幕模型输出**输入生产处理器，使用内存响应、**零网络调用**；30 份全部通过来源身份、条目数量、ID、revision 重建。[回放指标](caption-production-replay.json)只包含哈希、数量和结果，未提交完整字幕。

它仅验证实际模型输出与新协议的兼容，不验证新提示质量，也不改变历史漏译、碎片和慢响应结论。连续播放和正式字幕提示实站调用仍在 L04 验收。
