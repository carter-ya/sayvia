# S04b 翻译计划与格式重建验证

- 日期：2026-10-30
- 基线：S04a 66f54f1，直接依赖 PR #5
- 范围：原始区间 Markdown／纯文本／DOM 计划、模型载荷、严格结果重建、12 条固定样例
- 环境：macOS arm64，Node 22.23.2，pnpm 10.21.0，Playwright Chromium 156.0.8078.4

## 实现与验证

使用 remark-parse、remark-gfm 与 mdast 原始位置，只把自然语言叶子范围作为候选。按原文切片重建，不全文 stringify。代码、HTML（包含内联成对标签中的正文）、链接目标、换行、列表／表格标记、转义序列和实体留在本地。图片 alt 和完整引用链接标签可译；快捷／折叠引用的标签同时是标识，原样保留。

URL、邮箱、GitHub 用户／团队提及和 Issue 引用同样用于纯文本与 DOM 路径；DOM 另使用源元数据保护代码。普通正文 timeout 保持可翻译。纯代码、纯 URL 等内容不需要模型请求。

不可变计划保存源串与精确区间；模型载荷仅包含有序可译片段及无正文的保护占位，不包含源代码、隐藏链接目标或人工参考答案。结果必须是严格 JSON，片段 ID 数量、顺序与类型一致；缺失、重复、未知字段、额外解释、控制字符、不完整 Unicode、额外换行和过长输出均拒绝，不自动补修或再次请求。

Markdown 重建复查解析后的结构及受保护属性。先进行必要内联转义，若行首标点产生结构，再本地加强转义复查。测试实证 GFM 仍会把转义网址识别为自动链接，因此新增此类链接以 FORMAT_CHANGED 拒绝；不依赖反斜杠声称安全。普通英文标点、连字符与撇号不无故改成转义文本。

完整 pnpm check 通过类型、静态检查、格式、生产构建、95 项单元／生产包测试和 13 项 Chromium 测试。本层新增 37 项单元测试，浏览器沿用前序回归；核心格式计划不依赖 DOM，可在后续 Dedicated Worker 中运行。

## 质量样例与边界

src/evaluation/samples.ts 固定 12 条自制公开样例，覆盖三种来源、两个翻译方向、否定／条件／数字、技术词、代码、链接／alt、引用、HTML、GFM 表格／任务列表、URL／邮箱／用户提及、换行。每条包含人工参考含义、保护内容与评审关注点，供 OpenAI 和 DeepSeek 使用同一组输入。

本层只验证原文直返无损及合成译文的格式重建，没有调用任何真实模型，也不把参考含义当作已生成译文。按片段翻译可能损伤自然语序，必须在 S05 跑真实模型评估后决定是否调整算法。未知或没有可靠原始偏移的 Markdown 结构失败关闭；不得把不完整计划送给模型。

当前校验针对按片段返回的模型结果；用户编辑完整译文后的替换资格校验须在后续写作流程接入时完成，不能绕过此层保护规则。尚无模型请求、付费调用或最终 UI；M1 未通过。
