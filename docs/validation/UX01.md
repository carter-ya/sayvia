# UX01 翻译体验修正

日期：2026-11-01。依据用户四项实际体验反馈调整，替代此前按主机手动授权与逐站启用的交互要求。

## 最终行为

- 安装时声明普通 HTTP／HTTPS 的网页与模型请求主机权限，去除插件内“授权 API 主机”和网站启用页面。Chrome 管理安装／更新确认及网站访问限制；后台仍检查有效权限和保存的 API 地址，不越过受限页或开放任意请求 URL。
- 设置默认聚焦模型连接；配置名称可空，使用截取后的模型名称。原有 Key 留空保留，偏好与清除数据在“更多设置”。旧配置结构及凭证不做破坏性迁移，旧 allowedSites 不再用作第二个启用开关。
- 选区入口为 26px，指针选择定位在松开位置附近，键盘选区使用最后一行。两种路径都约束在视口内；选中和显示图标不调用模型。
- 页面浮窗宽 340px，原文与低频选项折叠，保留语言、可编辑译文、翻译／取消、复制及必要写作操作。去除宣传标题、重复模型和就绪说明；工具栏概览也删除重复文案。

## 复现与验证

修改前，新增实际扩展场景确认仍有 API 授权按钮、普通网站没有默认可用的选区入口；源码使用整段选区外包矩形右下角，解释了多行选择时图标远离鼠标的问题。修改后，多行真实 pointerup 坐标、26px 尺寸、视口边缘、键盘回退、紧凑浮窗和无逐站设置流程通过实际 Chrome 扩展测试。

完整本机检查：类型、lint、格式、331 项单元及 88 项浏览器通过。浏览器回归保留键持久化与同 ID 更新、来源隔离、原文修改／撤回保护、IME 期间禁止写入、受控编辑框状态、恢复冲突、真实剪贴板、取消与后台恢复、连接测试与会话清理。移除旧授权交互的断言，用安装权限、浏览器限制和默认可用流程替代；不通过放宽草稿或凭证保护来简化 UI。

网站访问限制的端到端用例模拟 Chrome 的权限判断与后台停用通知，单元另验证实时权限拒绝与任务取消；不宣称自动操作了用户个人配置的原生权限界面。界面截图使用隔离配置与自制内容，候选文字可通过正式编辑控件调整作排版预览，不作为真实翻译质量证据。

普通 CI 和本轮 UI 验证不调用真实模型、不读取用户浏览器 Key；旧模型报告仅证明其注明的翻译核心版本。新增权限的个人浏览器升级确认、真人语义及正式发布条件仍按发布检查单执行。合并仍须最新 head 的 Codex 无有效问题且远端 CI 成功。
